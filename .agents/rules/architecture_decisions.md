# Architectural Decision Persistence Rule

Whenever making major coding decisions, choosing libraries, changing the database schema, modifying authentication/authorization, or introducing new architectural patterns in this workspace:

1. Always read and refer to `DECISIONS.md` located at the root of the workspace.
2. Update `DECISIONS.md` with an ADR entry (following the template in `DECISIONS.md`) documenting:
   - The Context & Problem
   - The Decision & Implementation details
   - The Consequences, Rationale, and Trade-offs
3. Never remove previous decisions; mark them as superseded if replaced.
